# 两两轮转空闲负载（12 会话 = 6 对，6 个顺序空闲窗口）

> 设计目标：任何时刻 2 条空闲、10 条活跃。
> **实测达不到「始终 10 条活跃」**：偏移起跑让前期只有 2–4 条在跑，
> `10 条活跃` 只在最后 1–2 个窗口成立（见 §4.1 的三条前提）。

## 1. 构造

| 旋钮 | 值 | 说明 |
|---|---|---|
| 会话数 | 12（6 对） | APIGenMT，L@turn10 ∈ [3.2k, 3.8k]，截断到 12 轮 |
| `gap_s` | 1.5 s | 每对活跃 10 轮 = 15 s |
| `pause_after_turn` / `pause_s` | 10 / 15 s | 每对停 15 s 后恢复 |
| `arrival.offset_s` | 0, 15, 30, 45, 60, 75 | 每对比上一对晚 15 s 起跑 |
| `pool` | 35,975 | ΣL(turn10) = 42,611 → **1.18× 溢出** |
| 派生量 | `m = pool/L̄ = 10.3`，`n_a = 10`（满编时），`n = 12` | `10 < 10.3 < 12` ✓ 形式上临界，实际活跃数前期不足 |

时间轴：

```
pair i : 活跃 15 s → 空闲 15 s → 恢复
pair i+1 比 i 晚 15 s 起跑
⇒ 窗口 i = [15(i+1), 15(i+2)]，期间 pair i 空闲，pair i+1..i+5 活跃（恰好 10 条）
⇒ 窗口首尾相接，任何时刻恰好 1 对（2 条）空闲
```

窗口内的压力：10 条活跃会话 15 s 内各写 10 轮 × ~200 token ≈ **20k** 新内容，
而空闲对只有 ~7k —— 足以把它们削掉。

## 2. 结构性限制（重要）

对"静态轮转 + 同时最多 k 条空闲"的负载，有：

```
溢出量 O = ΣL − pool = (n − m)·L
空闲集合在任意时刻的足迹 = k·L = (n − n_a)·L
而临界条件要求 m > n_a  ⇒  O < (n − n_a)·L = k·L
```

**即：只要活跃组装得下，溢出量永远小于空闲集合的足迹，空闲组不可能被整体清空。**
本格 k=2、n−m=1.7 → LRU 最多削掉空闲对的 1.7/2 = 85%。

所以这个负载是**温和压力**构型，与 burst 实验（`ΣL/pool ≈ 1.5–1.9`、空闲组被整体清空）本质不同。

## 4. 结论

1. **这一版 RR 全面更差**：回归总重算 +34% / +55%，全量命中 −0.5 / −0.7 pt，
   TTFT p50 +20% / +52%。最差轮也更差（0.827 → 0.714）。
   —— 与第一版（`roll2`，轮转未生效）"RR 削峰"的结论**相反**，说明那次的"削峰"是伪影。
2. **压力太轻，根本没到临界区**：回归时前缀保留 **0.83–0.95**，12 个回归请求的总重算只有 4.8k
   （平均 404 token/条），几乎没东西被驱逐。
3. 原因有两层：
   - **结构性**：`n_a < m` 时溢出量 `< 空闲足迹`（§2 已证），空闲对不可能被清空；
   - **实现性**：偏移 15 s 起跑意味着一开始只有 2–4 条会话在跑，
     `10 条活跃` 要到最后一两个窗口才成立，池子前期远未填满 → 实际压力比设计估算低得多。
4. **结论：这个负载不能用来证明 RR 的收益**。它反而给出了一个清晰的反例：
   **在没有真实容量压力时，RR 会白白损失命中率（−0.5~−0.7 pt）和 TTFT 中位数（+20~52%）**。
   这与 P1（ρ=1.2 → RR −2 pt）方向一致。

## 4.1 要把"两两轮转"做成临界区，需要满足

```
① 12 条会话在 t=0 同时起跑（否则前期活跃数不足，池子填不满）
② 各对的 pause 落在不同轮次 → 需要 ≥ 60 轮的会话（APIGenMT 只有 12–26 轮 → 用 alfred，max 161 轮）
③ n_a 与 m 贴得很紧：m ∈ (n_a, n_a + 0.5]，让溢出量接近一轮空闲足迹
   （本格 m=10.3、n_a=10 → 溢出只有 0.3L，远小于 2L）
```

满足这三条时才能同时做到"始终 10 条活跃"和"某一对被真正清空"。按当前数据供给
（alfred 161 轮、90 token/轮）可以构造：pool 36k、L≈3.3k（第 36 轮）、pause 轮次 10/20/30/40/50/60。

## 5. 复现

```bash

for cfg in '{}' '{"fair_rr":true,"kappa":0.5}' '{"fair_rr":true,"kappa":0.3}'; do
  POOL=burst_roll2 POLICY=rr WAIT_SCALE=1.0 SEED=42 TAG=roll3_test POLICY_CFG="$cfg" \
    bash tailshot/run_large.sh
done
# 注意：build_rolling_pool.py 的偏移必须是 GAP_S*PAUSE_TURN(=15s)*i，不能是 GAP_S*i
# 验证：起跑应为 0/15/30/45/60/75 s，回归约 47/58/76/88/106/121 s
```
