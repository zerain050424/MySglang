# Design1 · 计算感知的公平轮询淘汰（DRR + 视界加权）
---

## 1. 目标

把如何淘汰从全局取最小分数改成**会话级公平轮询**，使单次淘汰造成的单会话损失有上界，
避免最冷的一条会话被整链清零、同批其他会话毫发无损"。
选择规则只有一条：
```
每次淘汰，选出让 P_i · d_i 最小的会话，剪掉它链尾的一个片段。
```

`P_i` = 会话 i 的视界内回归概率，`d_i` = 会话 i 当前的 KV 缺口（token 数）。

---

## 2. 三个量的定义

### 2.1 `d_i`（缺口，单位 token）

```
d_i = L_i − retained_i
```

- `L_i`：会话当前链长 = 最近一次请求的 prompt 长度。
- `retained_i`：从根开始**连续**保留的前缀长度（radix 匹配的实际命中长度）。

`d_i` 在会话每次请求后**直接观测**：`d_i = prompt_tokens − cached_tokens`。
两次请求之间按被淘汰的片段长度增量累加：`d_i += len(value)`。

观测值覆盖累加值。共享前缀、分支点导致的归属歧义由这个覆盖动作自动修正。

### 2.2 `L_i` 的维护

- 会话每次请求后更新为 `prompt_tokens`；
- 会话无请求时，取该会话子树内节点的最大 `abs_start + len(value)`。

### 2.3 `P_i`（视界内回归概率）

视界 `H` = 池子周转时间：

```
H = pool_tokens / EMA(写入速率, tok/s)        # 取 [30s, 1800s]
```

`P_i = F_i(idle_i + H) − F_i(idle_i)`，`F_i` 是该会话轮间隔的 lognormal CDF。

含义：**这份 KV 在被再次挤掉之前，它会不会回来。**

`F_i` 的参数按会话自身历史估计：

```
m_i = median(该会话历史轮间隔)                 # n_i ≥ 3 时用自身
σ_i = 1.0                                      # 固定形状，不拟合
m_i = (n_i·m_i + k·m_workload) / (n_i + k)     # k = 3，向 workload 先验收缩
```

`H` 让 `P_i` 与集群规模无关：同一套参数在小池子和大池子上都成立。

---

## 3. 权重进入排序的方式

键取最小：

```
key_i = ( P_i · d_i , −L_i )
```

- 低 `P` 的会话允许积累更大的绝对缺口（它更可能不再回来）；
- 高 `P` 的会话缺口一旦变大就立刻排到前面，被保护；
- 平局按长链优先剪，减少占用。

**不使用 `d_i / P_i`。** 除法形式在 `P→0` 时键趋于无穷，等于把死会话永久锁定在池中。

---

## 4. 护栏

### 4.1 绝对缺口上限

```
d_i ≤ κ · L_i        κ = 0.5
```

`P·d` 排序允许低 `P` 会话承担远大于平均的损失。加这条之后，单会话损失有硬上界，
最坏情况不再依赖 `P` 的准确性。

### 4.2 最小保留前缀

```
retained_i ≥ max(512, 0.3 · L_i)
```

链头承载 system prompt 与任务指令，整段丢失的代价不在 TTFT 里体现。



TTL 是 pin 的组成部分，不是可选项。

### 4.4 权重量化与节流

- `P_i` 量化为 `{1.0, 0.5, 0.2, 0.05}` 四档；
- 权重每 200 ms 或每 8 次淘汰刷新一次；
- 跨档需要连续两个刷新周期，避免排序抖动。

排序只依赖相对大小，四档足够。

---

## 5. 会话状态

| 字段 | 来源 | 生命周期 |
|---|---|---|
| `L_i` | 请求的 prompt_tokens | 会话首次插入时创建 |
| `d_i` | 请求的 prompt−cached；片段淘汰时累加 | 同上 |
| `gap 样本` | 相邻两次请求的时间差 | 同上 |
| `P_i` | 由 `idle_i, m_i, H` 计算 | 每 200 ms 刷新 |
| `state / pin_deadline` | 客户端上报（可选） | 收到信号时更新 |

会话在以下条件之一被回收：子树内已无节点；或距最后一次请求超过 1 小时。

`session_id` 缺失的请求不进入会话级记账，退化为按 workload 的 DRR（同一 workload 视为一个会话）。

---

## 6. 完整规则

```
evict(num_tokens):
    刷新 P_i（若已到刷新周期）
    循环直到 num_evicted ≥ num_tokens:
        candidates = 可淘汰叶子中，其所属会话满足 d_i < min(κ·L_i, L_i − min_retain) 的部分
        若 candidates 为空: 依次放宽到 d_i < κ·L_i，再放宽到全部叶子
        victim = argmin over candidates of (P_i · d_i, −L_i)
        释放 victim，d_{owner(victim)} += len(victim.value)
```

`owner(node)` = 该节点子树内 `L_i` 最大的会话。

band-0（one-shot：random 整请求、单轮 response 段）的行为保持不变，本设计只作用于 band-1。

---

## 7. 不变量

1. 任意时刻 `d_i ≤ κ · L_i`（护栏生效期间）；放宽路径触发时记一次 overshoot 事件。
2. 单次 `evict()` 内，任一会话的损失上界 ≈ `总量 / 活跃会话数 + 最大片段长度`。
3. `P_i` 只影响顺序，不影响总量：同样的 `num_tokens` 始终被释放。
4. 键值不出现除法与无穷；`P_i ≥ 0.05`，`d_i ≥ 0`。

---

## 8. 与现有实现的差异

| | 现有（`SimpleHybridStrategy` + 全局 `min(victim_key)`） | Design1 |
|---|---|---|
| 竞争单位 | 节点 | 会话 |
| 分数维度 | `reuse_score(node)`，会话内所有节点同分 | `P_i · d_i`，随缺口变化 |
| 谁挨刀 | 全局最小分数者，直到其链被抽干 | 缺口加权最小者，每轮只剪一个片段 |
| 单会话损失上界 | `min(淘汰总量, L_victim)` | `κ·L_i` |
| 时间常数 | 全局 lognormal(1.81, 1.092) | 会话自身间隔中位数 + 视界 `H` |
| 抖动来源 | 分数在一批会话间翻转 | 四档量化 + 节流 + 迟滞 |

## 10. 参数表

| 参数 | 默认 | 说明 |
|---|---|---|
| `κ` | 0.5 | 单会话缺口上限（占链长比例） |
| `min_retain` | max(512, 0.3·L) | 最小保留前缀 |
| `k`（收缩） | 3 | 向 workload 先验收缩的强度 |
| `σ_i` | 1.0 | 间隔分布形状，固定 |
| `H` | pool / EMA(write) | 视界，clamp [30s, 1800s] |
| 量化档 | {1.0, 0.5, 0.2, 0.05} | 权重档位 |
| 刷新周期 | 200 ms / 8 次淘汰 | 权重重算节流 |
| `pin TTL` | 2 × expected_tool_latency，默认 120s | 状态 pin 有效期 |
| 会话回收 | 1 h 无请求 | 状态清理 |
