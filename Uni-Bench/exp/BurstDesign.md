# 临界并发 + 稀疏活跃 + 回归浪潮：负载与实验设计

> 目标：把 `n_a < m < n` 这个"必须驱逐空闲缓存以保住活跃缓存"的区间做成可复现的实验构型，
> 让 LRU 的"整链清零"暴露为 **TTFT p99 尖峰**，而 RR-EVICT 的"保头"表现为**削峰**。

符号：`n` 会话总数，`n_a` 同时活跃数，`m = pool / L` 缓存容量（以会话为单位），
`L` 单会话链长（token），`pool` 可用 KV token 数。

---

## 1. 三个原则 → 可控参数

| 你的原则 | 实验旋钮 | 落点 |
|---|---|---|
| **① 临界并发 `n_a < m < n`** | `n_a`（活跃任务组会话数）、`n_i = n − n_a`（空闲组）、`L`、`pool` | `ΣL/pool ∈ [1.2, 1.6]`（溢出但不剧烈）；`n_a·L/pool ∈ [0.5, 0.7]`（活跃装得下但吃紧） |
| **② 稀疏活跃 + 重前缀** | idle 组的 `pause_after_turn` + `pause_s`；`L` 由**长链会话子集**筛出 | `L ≈ 7k`（冷 prefll 1.4 s）；长 idle 一次 45 s，占整轮 60%+ |
| **③ 回归浪潮** | idle 组所有会话**同一轮次 + 同一 pause 长度**（到达 step 0.05 s 对齐） | 唤醒抖动 < 1 s，形成 8 条同时回归 |

## 2. 第四个约束（我们实测得到，必须同时满足）

DRR 的实际保护是 `_loss_cap = κ·L`。若**保住所有人的头就已经塞满池子**，护栏会同时饱和、
退化到"按缺口最大者继续删"的兜底路径（实测：`max_recompute` 与 base 逐位相同）。

```
条件 ④:  Σ(κ·L_i) / pool < 0.8        （κ=0.5 时即 n·L/pool < 1.6）
```

四个条件合起来给出的可行域（`pool = 73,120`，`κ = 0.5`）：

```
n_a·L / pool ∈ [0.5, 0.7]        ← 活跃装得下
n·L   / pool ∈ [1.2, 1.6]        ← 全体装不下
m = pool/L  ⇒  n_a < m < n
```

## 3. 推荐主格（S 格）

| 参数 | 取值 | 依据 |
|---|---|---|
| `pool` | **73,120** | `--mem-fraction-static 0.79`（实测 35,975 装不下长链） |
| `L` | **7,000**（筛 `L ∈ [6k, 9.5k]` 的会话） | 冷 prefill 1.43 s，肉眼可见 |
| `n_a` | **6** | 6×7k = 42k = 57% 池 |
| `n_i` | **8** | 8×7k = 56k |
| `n` | 14 → `m = 10.4` | 6 < 10.4 < 14 ✓ |
| `ΣL/pool` | 1.34 | 必须驱逐 25k |
| `ΣκL/pool` | 0.67 | 护栏可满足 ✓ |
| 活跃组 | `gap_mode: fixed, gap_s: 1.0`，无 pause | 持续写入 = 压力源 |
| 空闲组 | 同 gap，`pause_after_turn: 10`，`pause_s: 45` | 45 s 内活跃写入 21.6k，吃掉 ~2/3 空闲内容 |
| 唤醒 | 空闲组同一轮次醒，抖动 < 1 s | 回归浪潮 |

**预期（用实测 prefill 4,887 tok/s 估算）**

| 指标 | LRU（base） | RR-EVICT | 差异 |
|---|---|---|---|
| 被整链清空的空闲会话 | **≈ 6.7 / 8** | 0（保留 50%） | — |
| 单条冷回归 prefill | 7.0k → **1.43 s** | 3.5k → **0.72 s** | **2×** |
| 回归浪潮总量 | ~47k → 9.6 s 串行等价 | ~28k → 5.7 s | 1.7× |
| TTFT p99（浪潮窗口） | 秒级 | 亚秒级 | 主判据 |

## 4. 时间轴

```
t=0 ── 14 条会话同时起跑（step 0.05s），turn1..10，gap=1s
        ↓ 全部建好 7k 前缀（活跃 42k + 空闲 56k = 98k > 73k → 第一次溢出）
t≈10s ── 空闲组 8 条进入 pause（45s）；活跃组 6 条继续跑
        ↓ 活跃组写入 540 tok/s（6 × 90 tok/轮 ÷ 1s）
        45s 内注入 21.6k → 按 LRU 顺序吃掉 ~2/3 空闲内容
t≈55s ── 8 条空闲会话**同时**回归（turn 11 起）
        ↓ burst 窗口：观察 TTFT / queue / prefill 峰值
t≈65s ── 再跑 5 轮，观察恢复
```

## 5. 消融矩阵（12 格，每格约 90 s）

| 组 | 变更 | 目的 | 格数 |
|---|---|---|---|
| **S** | 主格 | 建立基准 | 2 |
| **A** `n_a` 扫描 | 3 / 9 / 12（其余同 S） | 3=压力不足（`m > n_a` 但空闲不溢出）；9=更紧；**12 > m=10.4 → 抖动**，预期两者都崩 | 6 |
| **B** `L` 扫描 | 3.5k（`ΣL/pool=0.67`→不溢出）/ 10k（`ΣL/pool=1.9` 剧烈） | 验证"重前缀"与溢出强度的作用 | 4 |
| **C** 唤醒对齐 | 抖动 0 s / 10 s（`pause_s` 加 ±5 s 抖动） | 验证"浪潮"是 p99 尖峰的必要条件 | 2 |
| **D** `κ` | 0.5 / 0.3 | 保头比例的边际效应 | 2 |

每格都跑 `fair_drr=false` 与 `true` 两个策略 → 共 **2×14 = 28 次运行 ≈ 45 min**（含起停）。
若只跑 S 组 + A 组（`n_a`=3/12）+ C 组：**8 格 ≈ 20 min**。

## 6. 指标（这是设计的要害）

我们已实测：RR 在"平均命中率"上会输（ρ=1.2 时 −2 pt），但在"最坏一次重算"上会赢（−28%）。
所以本实验的主终点必须按"浪潮"定义：

```
burst 窗口 = 空闲组 turn == pause_after_turn + 1 的请求（8 条，同时到达）
主终点:  TTFT p99（窗口内）、max queue_time_ms、max prefill_ms
次终点:  burst 内总 prefill token、恢复期（turn+2..+6）TTFT p50
反证指标: 全量平均命中率、全量总重算 token   ← RR 可能更差，必须如实报告
守卫:    burst 内 8 条请求的时间戳跨度 < 1.5 s（否则"浪潮"不成立，该格作废）
```

判定：**RR 有效 ⟺ burst 窗口 `TTFT p99` ≤ 0.6× LRU 且 `max queue` ≤ 0.6× LRU**。

## 8. 风险

| 风险 | 现象 | 预案 |
|---|---|---|
| 活跃组增长吃掉池子 | 窗口末活跃占比 >0.9，RR 也被迫削活跃 | 缩短 `pause_s` 到 30 s（活跃增长 ≤ 22%） |
| 唤醒不同步 | 8 条回归时间跨度 >1.5 s | step 0.05 s 已知足够；否则 idle 组用同一 `seed` |
| 压力不足 | LRU 清空 <4 条 | 提高 `n_i` 或 `pause_s`；或把 `L` 提到 8k |
| 溢出过猛 | 两策略都崩（hit <40%） | 降 `n_i` 或 `L`；参考 §2 的可行域 |

## 9. 与已有结论的衔接

- **Cascade R2/R3**（`n_a=0` 的极端：没有活跃组，压力全靠搅拌流）→ RR 大赚；
- **LargeScale P1**（`n_a = n` 的极端：全部活跃，无稀疏）→ RR 中性或负；
- **本实验**（`n_a < m < n` 的中间区）应落在两者之间，且给出"收益随 `n_a` 变化的曲线"。

这条曲线就是理论图 4 的实测版本。

## 结论 1：溢出比是硬门槛，S 格（73k）无效

S 格实际常驻 = active 26.9k + idle 52.8k = 79.7k，只超出 pool 6.6k（**1.09×**） →
空闲组返回时前缀命中仍 0.96，**什么都没被驱逐**，实验不成立。

> **修正设计规则**：`ΣL / pool ≥ 1.3`；只算"空闲组 + 活跃组末态"的常驻量。
> 之前按 `452 tok/轮` 估增长，实测这批会话只有 `~200 tok/轮`，导致溢出量被高估。

## 结论 2：pool 36k 进入临界区，LRU 的惩罚被放大

burst 命中从 0.96 掉到 **0.26–0.56**，TTFT p50 从 72 ms 涨到 **537–711 ms（7–10×）**，
`max queue` 最高 502 ms（队头阻塞）。→ 你的三条原则中"临界并发 + 重前缀 + 回归浪潮"确实能把
LRU 的缺陷放大成可测的 TTFT 尖峰。

## 结论 3：DRR 在三组里全部更差，且原因是"上限没生效"

| 对照 | burst 命中 | burst 总重算 | TTFT p50 |
|---|---|---|---|
| S36 base → DRR | 0.358 → **0.257** | 31.4k → 36.3k | 537 → 711 ms |
| S36b base → DRR | 0.564 → **0.409** | 21.3k → 28.8k | 576 → 560 ms |

实测保头比例：DRR 下 idle 会话只保住 **1.4k / 5.8k = 24%**，而 `κL = 0.5 × 5.8k = 2.9k`。
**即 d = 4.4k > κL，上限被突破 1.5k** —— 与 `_pick_in_queue` 的两级 relax 在饱和时全部跳过、
落到 `max(d)` 兜底分支的推断一致。

而且 DRR 把 base 的"集中损失"（4 条完好 + 4 条清零）变成"均匀损失"（8 条都掉到 24%）：
在"全员同时回归"的场景里 **max 不变、总量更差**。

## 因此：要验证理论上的 2× 收益，必须把上限做成硬的

```
当前实现：按 (p·d, -L) 排序 + d ≥ κL 的过滤   ← 压力一大就退化成兜底
需要的实现：每会话硬配额（quota_i = κL_i 被淘汰的上限），
            配额用尽后该会话直接从候选集移除，其余由 LRU 兜底
            （即"钉住 + LRU"，而不是"公平轮询"）
```

只有在硬配额下，"RR 保留 50% → burst 单条 prefill 减半 → TTFT p99 减半"这条因果链才可验证。

# 硬配额 + 朴素轮询：全量实测（2026-10-27 21:00–21:53）

实现：`fair_rr: bool`（`evict_policy.py`，约 60 行）
  - 配额 `quota_i = _loss_cap(L_i) = min(κL_i, L_i − max(512, 0.3L_i))`
  - `d_i ≥ quota_i` → 该会话**退出候选集**（硬准入，不是排序过滤）
  - 候选里取 `_rr_last` 最小者（最久没被服务），服务后 `_rr_last = seq++`（排到队尾）
  - 全部配额耗尽 → `_quota_breach += 1`，退回 `min(victim_key)`（LRU）
  - 配额由 `touch` 重置（会话自己写入时 `d` 归零）→ 每轮都有新配额

## 结论

1. **"配额作为准入条件"是这次起作用的关键**：同样的 κ、同样的会话，
   从"排序时过滤"改成"配额用尽即出候选集"，效果从 −2~−4 pt 变成 +3~+8.5 pt。
2. 收益集中在**临界区**（`ΣL/pool ≈ 1.3–1.8`）：无压力时持平，抖动区仍有小幅收益。
3. 4 个独立池种子全部为正（符号检验 p ≈ 0.06）；加上抖动格 5/5。
4. 仍需补：每格重复 2–3 次以估噪声；跨 `L` 分布的稳健性；`κ` 的自适应规则
   （`κ_eff = min(κ, (pool − active) / ΣL_idle)`）。
