# 大规模验证实验方案（Cascade-L）

> 目标：在 **不引入跨队列淘汰**的前提下，使用**数十条、真实分布、多随机种子**，验证会话级公平淘汰（DRR）在真实负载形态下
> 是否有效、在什么条件下失效。

## 4. 预注册假设与判定规则

| 编号 | 假设 | 判定（成立条件） |
|---|---|---|
| **H1** | 无跨队列压力时，级联仍存在且随 ρ 单调加剧 | baseline 的 `wipe_rate` 随 ρ 单调上升，且 ρ=2.0 时 ≥ 20% |
| **H2** | DRR 在高压力下消除级联且不损吞吐 | ρ≥1.6 格：`wipe_rate` 降 ≥50%、`max recompute` 降 ≥30%、命中率不降 >0.5pt |
| **H3** | 轻压力下 DRR 无收益甚至有害（需 guardrail） | ρ≤1.2 格：DRR 的 p99 或命中率变差 >5% |
| **H4** | 级联的尾部代价 ∝ 受害者链长 | P2 中"最冷会话为长链"时，其 resume 代价与 L 回归斜率 ∈ [0.8, 1.2] |
| **H5** | 结论对 idle 模型不敏感 | P3 四种 idle 模型下 H1/H2 的**方向**一致（4/4；若仅 ④ 偏离，说明 ε 是关键变量） |

**反证条款（必须如实报告）**：若 H1 不成立（无搅拌时 `wipe_rate ≈ 0`），
则结论应改写为"级联是**跨队列资源竞争**的表现，而非纯会话公平问题"——
这会直接改变你后续跨队列策略的设计优先级。

## 5. 时间轴：从 burst+pause 到逐轮独立采样

Cascade 三格的时间轴是 **burst → 屏障 → 统一 pause**：12 条会话同相位、同节奏，
`gap` 只有 4 个原子值（1 / 10 / 30 / 90 s）。这适合做存在性证明，但**冷会话是被分组
标签指定的**，`Simultaneity` 也是构造出来的。

大规模实验改为 **逐轮 preassigned**（`gap_mode: preassigned`）：

| | Cascade（burst+pause） | LargeScale（preassigned） |
|---|---|---|
| 间隔来源 | 每 task 一个常数 | 每会话每轮独立采样 |
| 同步机制 | `BurstGate` 屏障（12 条全过第 20 轮） | **无**（配置里不写 `pause_after_turn`） |
| 长 idle 位置 | 固定在 turn 20 | 按分布落在任意轮（实测相对位置 p10 0.08 / p50 0.46 / p90 0.90） |
| 长 idle 长度 | 10/30/90 三个值 | 连续分布（中位 210 s，p99 26,985 s） |
| 会话间节奏 | 三组同频 | 每会话中位 gap 0.09–2.2 s 不等 |
| 冷会话来源 | 分组标签 | 分布自然产生的离群 |

已实现三件：

```
① bench_unicache.py          gap_mode: preassigned → 读 turn["gap_s"]
② exp/idle_model.py          四个 idle 模型，逐会话逐轮采样
③ exp/build_large_pools.py   按 ρ 采样 + 写 gap_s + 生成 yaml（无 pause_after_turn）
```

示例池（`--rho 1.2 --model claude --max-turns 20 --max-gap 300`）：
22 会话 / 439 轮 / ΣL 43,383 / ρ=1.205。

### 5.1 时间尺度：`--wait-scale` 能压到多少

级联是否发生，取决于 **一次 pause 期间到达的内容能否覆盖池子**，记
`R2 = 到达 token / pool`。实测（22 会话、每轮新增 99 token、pool 36k）：

| s = wait_scale | 单次运行 | pause 中位（墙钟） | R2 | burst/pause 比（真实 175） |
|---|---|---|---|---|
| 1.00 | 254 min | 95.6 s | 0.17 | 175 |
| 0.10 | 26 min | 9.6 s | 0.16 | 21 |
| 0.05 | 14 min | 4.8 s | 0.15 | 12 |
| 0.02 | 6 min | 1.9 s | 0.14 | 5 |

**两条结论**：

1. `R2` 对 s 几乎不变（pause 与到达速率同比缩放）⇒ 压缩**不改变**"一次 pause 能造成
   多少损失"，只压缩 burst/pause 比（请求时延是硬下限）。推荐主格 `s=0.1`、扫描格 `s=0.05`，
   报告里注明该比值。
2. `R2 ≈ 0.16`（ρ=1.2）说明一次 pause 只换掉 16% 的池子，冷会话只会被**部分**削；
   要复现"整链清零"需要 ρ ≈ 3。真实部署 ρ≈500（147k 上下文 × 247 并发 / 单卡池），
   所以级联在生产里是常态。

## 5.2 实验矩阵（精简版：10 次运行 ≈ 50 min）

策略维度：`fair_drr ∈ {false, true}`（baseline 与 DRR），其余默认
（`kappa=0.5`、`drr_use_p=false`、`drr_workloads=[multi_turn_agentic]`）。
**负载保持 alfred 不变**（不换成 APIGenMT），提速全部来自采样参数。

### 四个提速手段（都不改负载）

| 手段 | 做法 | 效果 |
|---|---|---|
| **① 截断过长空闲** | `--max-gap 300 → 90 s` | ḡ **34.6 → 15.3 s**，单次时长 ×0.44 |
| **② 压 `wait-scale`** | 0.05 → **0.02** | 单次 ×0.6（`R2` 不变，见 §5.1） |
| **③ 减 ρ 点** | 5 → **2 个**（1.2 / 2.0） | 运行数 50 → 8 |
| **④ 减种子** | 5 → **2** | 运行数再 ÷2.5 |

① 的合法性有实测支撑：该池**池周转时间 ≈ 7.5 s**，90 s 上限 = **12× 周转**。
空闲超过几倍周转时间后，会话必然已被完全清出，再长的空闲对缓存状态没有区别
（`build_large_pools.py` 会打印 `cap/turnover` 并在 <3× 时告警）。

### 批次 A：10 次运行

| 组 | 内容 | pool | ρ | N | idle | 种子 | 运行 | 单次 |
|---|---|---|---|---|---|---|---|---|
| **P1e** 等效性 | ρ=1.2 baseline，`s=0.05` | 36k | 1.2 | 22 | ④ claude | 1 | **1** | 6.6 min |
| **P1** 主格 | alfred，`s=0.02`、`cap=90` | 36k | **1.2 / 2.0** | 22 / 33 | ④ claude | **2** | **8** | 3.3 / 5.5 min |

合计 **≈ 50 min**（含 10 次起停约 10 min）。

实测池（`--rho 1.2 --max-turns 20 --max-gap 90`）：
**22 会话 / 431 轮 / ΣL 43,063 / ρ=1.196**，gap p50 0.43、p90 90、ḡ=15.3 s，
池周转 7.5 s。

| ρ | 轮数 | s=0.02 | s=0.05 |
|---|---|---|---|
| 1.2 | 432 | **3.3 min** | 6.6 min |
| 2.0 | 721 | **5.5 min** | 11.0 min |
| 3.0 | 1,081 | 8.2 min | 16.5 min |

### 可选加压（+16 min）

`ρ=3.0` × 2 策略 × 1 种子 = 2 次，单次 8.2 min。只在 P1 显示"ρ=2.0 级联仍不明显"时才需要。

### 精简的代价（必须写进报告）

1. **2 个种子** ⇒ 只能做符号检验（2/2），不能报"均值 ± 95% CI"。
2. **2 个 ρ 点** ⇒ 只能证"高压比低压更糟"，不能定位拐点；H3 的判据相应放宽为
   "ρ=1.2 时 DRR 无收益或变差"。
3. **`s=0.02`** ⇒ burst/pause 比 175 → **5**（burst 段已被请求时延主导）。
   用 P1e 这一格做等效性检查：若 s=0.05 与 s=0.02 的 `wipe_rate`/`hit` 差异 > 2%，
   则主格改用 s=0.05（时间 ×2）。
4. **`cap=90 s`** ⇒ 截掉了 1% 的超长空闲，但这部分对缓存状态等效（12× 周转）。

### 构造idle的四种模型（逐轮写入 `gap_s`）

```
① 固定三组      : 每条会话随机分配 10/30/90 s 中的一个长 idle，落在随机轮；其余 1.0 s
② 工具感知      : gap = Σ 工具耗时（按实测频次抽工具名 + 逆 CDF 抽时长）+ ε(cachewise 6.21 s)
③ 实测重放      : gap 从 parquet 的「离场时长 = tool_sum + gap」池 iid 抽（tool 轮），
                  人工轮从该 harness 的人工等待表抽
④ claude 型     : gap = Σ 工具耗时 + 0（ε 恒 0，见 exp/agent_trace_report.md §4）
```

人工轮：每轮以 π_h 概率视为"等用户"（默认 **0.137** = claude 实测），不执行工具。

### 批次 B（按 A 的结果决定，不在本次范围）

P2 链长异质 / P3 idle 敏感性 / P4 pool 消融 / B1 配重边界，各 4–12 次。

## 6. 指标

**主终点（三个，缺一不可）**

| 指标 | 定义 | 为什么是主终点 |
|---|---|---|
| `wipe_rate` | 被整链清零的会话数 / 总会话数 | 级联的直接定义，比计数更适合跨规模比较 |
| `wipe_rate_H` | 只统计"最长空闲 < 5×池周转时间"的会话 | **主终点（首选）**。空闲过长的会话必然不在池里，其清空与策略无关，必须剔除 |
| `max_recompute` | 单次 resume 需重算的最大 token 数 | 尾部代价，对应"用户等 1.1 s 的 TTFT" |
| `hit_agentic` | 仅 agentic 子集的命中率 | 不降是 DRR 的底线 |

**次终点**：p99 延迟、`HHI(组)`、`loss_quantum`、`resume_ttft`、`max(d_i/L_i)`、
`deficit_gini`（缺口集中度）。

**守卫指标（任一失败则该格作废）**

```
配置里不存在 pause_after_turn / BurstGate   证明时间轴不被屏障重新对齐
realized gap 分布 vs 目标模型 KS              每格核对，p > 0.05
Σ hit_tokens + Σ miss_tokens == Σ prompt_tokens   逐请求校验
d_i ≤ L_i                                     全部会话
OOM / 请求失败 / 超时                         必须为 0
队列等待 p99 < 0.1 × 平均 gap                  证明"并发未阻塞到达序"
```

## 7. 有效性与自检（先跑，再信结果）

1. **配对设计**：同一 `pool.jsonl`（含预置 `gap_s`）、同一 seed，分别喂给两种策略。
   数据与时间轴完全一致，差异只来自淘汰策略。注意 `gap_s` 由池构造阶段的 seed 决定，
   与驱动 `--seed` 解耦：换驱动 seed 不会改变时间轴（这是刻意的，保证对比纯净）。
2. **无同步断言**：解析出的 task_cfg 不得含 `pause_after_turn`；到达时间应为
   `0, 0.05, 0.10, ...`（错峰起跑）。若出现统一 pause，说明配置回退了 burst+pause。
2. **时间压缩等价性**：正式跑用 `--wait-scale 0.05`（6.3 s → 0.3 s）。
   在 ρ=1.2 格上对比 `wait-scale ∈ {1.0, 0.05}` 的 `wipe_rate`/`HHI`/`hit`，要求差值 < 2%。

   合法性依赖三个条件，逐条核对过源码：

   | 条件 | 现状 | 依据 |
   |---|---|---|
   | `drr_use_p = false`（默认） | ✅ | `horizon_s` 只在 `p_reuse()` 里用到，该路径不被进入 |
   | 单 workload（同一 `alpha_key`） | ✅ Track A / P2 | `reuse_score = alpha · reuse_prob`，只有一个 key 时 alpha 是公共乘子，不改排序 |
   | `update_interval=30 s` 墙钟触发 alpha 更新 | ⚠️ | 压缩后一次运行只有 ~2 次 alpha 更新（原本 ~40 次）；单 workload 下无影响，**B1（两 workload）必须用 `wait-scale 1.0`** |

   另外 `reuse_prob(idle)` 是 idle 的单调递减函数，等比压缩保序。
3. **确定性**：同 seed 连跑两次，`wipe_rate` 与事件序列必须一致。
4. **账户不变量**：每次运行后校验 `Σd ≤ pool`、`hit+miss=total`、`d ≤ L`。
5. **数据分布校验**：抽样池的链长分布 vs 总体做 KS 检验（p>0.05），
   防止分层抽样把分布改形。
6. **间隔模型保真度**：`tool_durations.json` 用 `(p,q)` 非均匀分位表（尾部到 99.99），
   与原始实测相比 p99–p99.99 最大相对误差 13.7%、KS ≤ 0.022。
   **禁止回退到 101 点等距表** —— 那会把 p99.9 放大 4–19 倍，凭空造出冷离群会话。
7. **池重置**：每格前重启 server（池与账本状态必须清零），
   当前残留的 pid 33911（`--max-total-tokens 50000`）需按格替换。

## 9. 风险与预案

| 风险 | 触发条件 | 预案 |
|---|---|---|
| 池上不去 | `mem-fraction 0.79` OOM | 回落 35,975，用 N≈17 达成同 ρ（P4 正在测这个等价性） |
| 压缩改变结论 | 等价性自检差值 >2% | 改用 `wait-scale 1.0`，只跑 P1 的 3 个 ρ 点（运行数降到 30） |
| wipe 太罕见 | ρ≤1.2 时几乎不发生 | 把该组改为"只报 `max d/L` 与命中率"，不强行追求 wipe 计数 |
| 长尾阻塞 | 161 轮的会话拖长单次运行 | 池构造时对轮数 >80 的会话降权（仍保留 10% 长会话） |
| 结论与 R1 冲突 | 轻压力下 DRR 又变差 | 这正是 H3，用于论证 S2c guardrail 的必要性，不算失败 |
