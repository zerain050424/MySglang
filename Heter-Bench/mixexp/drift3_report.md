# drift3 结果：构成漂移下 LRU / heter_cache / OPT（engine FCFS · page=8 · seed=42）

> 时间：2026-11-17 · 分支 `W1` · 单 seed（42），三段主导漂移
> 载体：`sim/` 的 `EngineSimulator`（FCFS 成批 prefill），跑生产 `HeterCacheRadixCache`
> 数据：`Heter-Bench/TaskData/drift3/`（15,309 会话 / 125 MB，`build_drift3_data.py` 生成）
> 设计 + gate：`Heter-Bench/mixexp/drift3_design.md`（gate 6/6 PASS）
> 结论速览：**背景越强，heter 的收益单调放大**（+0.13 → +1.49 → +3.95pp），收益几乎全部来自 chat 相位（+2.1 → +5.4 → +8.1pp）；**漂移本身很贵**：chat 相位稳态比同构成不切换低 16~25pp；**路径依赖可忽略**（逆序差 ≤0.2pp）。

## 4. 对比分析

### 4.1 背景越强，heter 的收益越大——假设被证实，且几乎全在 chat 相位

| 背景 | heter−LRU（overall） | P1 struct | P2 chat | P3 agentic |
|---|---|---|---|---|
| 0.5× | +0.13pp | −0.70pp | **+2.09pp** | −0.05pp |
| 1.0× | +1.49pp | −0.09pp | **+5.42pp** | +0.93pp |
| 2.0× | +3.95pp | +1.42pp | **+8.12pp** | +4.00pp |

单调性成立：背景越大（池周转越快），按"未来复用价值"保护越划算；而在低背景（0.5×）下，
池子宽裕到 LRU 的 recency 近似最优，heter 的保护反而是净负担（P1 甚至 −0.70pp）。
**chat 是唯一在所有背景档都稳定受益的相位**——它的共享前缀最长、被 recency 误杀的损失最大，
与 exp3 静态 cell 上的结论一致（chat cell 上 OPT 余量 22pp）。

### 4.2 漂移代价远大于构成效应，且集中的 chat 相位

P2(chat) 的稳态比"同构成不切换"低 **16~25pp**，是全场最大损失；P1(struct) −7.5~−8.9pp、
P3(agentic) −3.2~−6.3pp。机制解释：前一个相位（struct / trans 主导）把 chat 赖以命中的
**跨会话长前缀**挤掉了，chat 相位开始时这些块需要重新积累——而 chat 的单会话跨度 ≈500s，
1200s 的相位里只有约 2 代会话，恢复窗口不够。这也是 pos 4.3 里 T90 指标不敏感的原因
（主导类在自己的相位里始终处于"重新积累"状态，没有明显的"恢复到稳态"平台）。

推论（对策略设计的含义）：只按"下一步大盘命中率"调策略不够，**相位切换的瞬态**才是
损失主项；能跨相位保住长前缀的策略（正是 heter 的共享保护段）才有价值——这解释了
为什么 heter 的收益集中在 chat、且随背景增强。

### 4.3 OPT 上界随背景扩大：+4.45 → +5.94pp（相对 heter）、+4.58 → +9.89pp（相对 LRU）

高背景下选择余量被放大：池子越紧，"该淘汰谁"的信息价值越高。同时 OPT 在 P2 的稳态
（0.718 @1×、0.560 @2×）明显高于 heter（0.567 / 0.387）——chat 相位是策略差距最大的地方。

### 4.4 路径依赖可忽略

逆序（agentic→chat→struct）与正向的 overall 差 ≤0.2pp，与 heter−LRU 的差（0.13~3.95pp）
相比是噪声级。**结论不依赖相位顺序**（至少在这套构成与容量下）。

### 4.6 抬高 `value.horizon_s` **无效**（120 / 300 / 600 逐位相同）——是结构性的

试过 bg ∈ {0.5, 1, 2} × `horizon_s` ∈ {120, 300, 600}：**同背景下的 overall、分相位、
chat 稳态、漂移代价全部逐位相同**（`/root/sim_runs/drift3/horizon_sweep.json`）。

原因在 VD 的定义，不是"量级还没调到"：

```
VD_q = H_q(horizon) / max(occ_q, floor)         # 三个队列共享同一个 horizon
H_q(horizon) ∝ horizon × 该队列的命中速率        # 截断概率 P_return 里 elapsed+horizon 一起进
⇒ horizon 在跨队列排序里是**公因子**，相乘不改变升序
```

`QueueValueParams` 的文档也写死了这条：「视野是政策、W_q 只是统计；不要把时间常数按队列
拆开（稳态下等价于给队列加隐性权重）」。相位内 λ 恒定 ⇒ 速率估计与估计窗
`W_q = max(horizon, k·T50_q)` 的长度无关 ⇒ 排序与决策完全一致。

**结论：`horizon_s` 不是压 chat 漂移代价的杠杆。** 想动它必须让"跨相位长间隔复用"
以**非标量**方式进入判据（例如给高共享块一条与 VD 无关的保活通道，或让 `P_return`
的衰减对 chat 更慢），而不是乘一个更大的 horizon。

### 4.7 chat 漂移代价的性质：只有约 4.5pp 是容量，其余是瞬态

| 容量 | overall | P2 chat 稳态 | 同构成 stationary | 漂移代价 |
|---|---|---|---|---|
| 198k | 66.69% | 56.74% | 75.25% | **−18.5pp** |
| 396k（2×） | 68.91% | 64.85% | 78.83% | −14.0pp |
| 792k（4×） | 69.34% | 65.72% | 79.00% | **−13.3pp** |

- 容量翻倍只回收约 4.5pp，四倍后饱和在 −13.3pp ⇒ **主要不是"装不下"**：
  chat 相位的并发工作集约 606k token（λ 0.188/s × 跨度 500s × 6.45k token）是池子的 3 倍，
  但在 4× 容量下仍然贴着 −13pp，说明瓶颈是**瞬态**：进 P2 时池子被上一相位的内容占满，
  chat 要在 1200s 内、与 25% 背景 + 20% 陪衬争抢着重建前缀。
- 这段差距**在策略空间内是可回收的**：同一相位 OPT 稳态 0.718 vs heter 0.567（15pp），
  说明不是"信息不足"，而是"选择规则没把跨相位复用算进来"。

### 4.5 T90 指标本轮不好用（诚实记录）

用"主导类 60s 滚动命中率首次进入稳态−2pp 并连续 3 窗"定义 T90，结果多数相位是 0 或
360s、chat 在 OPT 下是 660s。原因是相位内构成同质、真正的构成变化只发生在边界一个瞬间，
而"稳态"取相位末 300s——切分点太粗。下一轮改成**逐相位用 60s 分箱画曲线**并直接报
"边界后第 1/2/3 个 100s 的命中率"，比单一 T90 更有信息量。

### 4.8 相位拉到 2400s：chat 的代价是**瞬态**，不是永久损失（并更正 3.3/4.7）

**先更正**：§3.3 与 §4.7 里的 −16.1/−18.5/−24.9pp 是高估的。原因是 stationary 对照的
稳态窗口取了 `t ≥ 相位末−300`，而 stationary run 的到达窗口结束后，长 chat 会话的后续
轮次仍在跑（且全部命中），把那 300s 的命中率拉到 0.99 量级。把窗口**严格限制在相位内**
（`[末−300, 末)`）后，同口径结果如下（`/root/sim_runs/stationary_fixed_window.json`）：

| 相位长度 | 背景 | P1 struct | **P2 chat** | P3 agentic |
|---|---|---|---|---|
| 1200s | 0.5× | — | **−9.1pp** | — |
| | 1.0× | −3.6pp | **−7.1pp** | +5.2pp |
| | 2.0× | — | **−8.5pp** | — |
| 2400s | 0.5× | — | **+3.4pp** | — |
| | 1.0× | −4.6pp | **−1.8pp** | −11.6pp |
| | 2.0× | — | **+3.3pp** | — |

结论：

1. **chat 的漂移代价是瞬态**：1200s 时 −7~−9pp，相位翻倍到 2400s 后落到 **±3pp（噪声级）**。
   也就是说 1200s 不足以让 chat 在"被上一相位污染的池子"里重建它的跨会话前缀；
   给到 2400s 就基本追平"同构成从 t=0 一直跑"的稳态。**"永久损失"的说法不成立。**
2. 直接证据：2400s 相位内 chat 的 300s 分箱是**平的**（bg=1×：0.55/0.55/0.59/0.57/0.53/0.56/0.56/0.51，
   末 3 箱 − 前 3 箱 = −0.019）——不是"还在爬升没爬到"，而是已经到顶；
   1200s 的相位只是把这个"到顶值"截掉了一部分重建期。
3. **agentic（P3）反方向**：1200s 时 +5.2pp（漂移反而更好，因为它继承了热池子、而 stationary
   的 agentic 冷启动更慢），2400s 时 −11.6pp。这一格**不稳定**且样本少（32→65 个会话），
   暂不下结论，需要 seed=43 + 更细的分箱再判。
4. struct（P1）两档都在 −3.6 ~ −4.6pp：单轮 + 共享模板，重建快，与相位长度基本无关。

2400s 矩阵本身（`/root/sim_runs/drift3_p2400/all_s42.json`）：overall 在 bg 0.5/1/2 下
LRU 73.96/60.92/43.66%、heter 72.81/61.23/44.74%、OPT 81.00/70.58/56.10%（OPT 的
时间轴固定点在这版**未完全收敛**：残差 6,511 / 7,784 条，需在正式引用前重跑收敛）。

### 4.10 chat 老化 TTL 180 → 300：三臂全量对比

motivation 来自 §3.5 的归因（59.5% 的 regret 是"chat 前缀已 reuse 4~6 次却被 TTL 老化清掉"）。
先做了 TTL 扫描（bg=1×，其余参数不变）：

| chat TTL | 0（关掉） | 60 | 120 | **180（原值）** | **300（新）** | 600 | 1200 | 3600 |
|---|---|---|---|---|---|---|---|---|
| 总体 | 66.06% | 61.14% | 64.87% | 66.69% | **66.84%** | 66.76% | 66.06% | 66.06% |

**是个倒 U**：60s 太狠（−5.55pp），180s 偏短，300s 是平台顶，>1200s 等于关闭老化
（1200/3600 与 TTL=0 逐位相同）。所以"去掉 chat 老化"不成立——老化对 chat 是**承重结构**：
关掉后陈旧前缀滞留池内、把 VD_chat 拉低，最后由队列级 VD 整队裁决，砍掉的是**还活着**的内容
（P2 自身 −2.5~−3.0pp）。正确动作是 180 → 300。

三臂（seed=42、page=8、cap=198k、engine FCFS、1200s 相位；LRU/OPT 不读该 TTL，
数字与 §3.1 逐位相同，验证了确定性与改动隔离）：

| 背景 | LRU | heter(300) | heter(180) | Δ | OPT | heter−LRU | OPT−heter |
|---|---|---|---|---|---|---|---|
| 0.5× | 76.92% | **77.23%** | 77.05% | +0.18pp | 81.50% | **+0.31pp**（180s +0.13） | +4.27pp（+4.45） |
| 1.0× | 65.20% | **66.84%** | 66.69% | +0.16pp | 71.65% | **+1.65pp**（+1.49） | +4.81pp（+4.96） |
| 2.0× | 47.49% | **51.74%** | 51.43% | +0.31pp | 57.38% | **+4.25pp**（+3.95） | +5.64pp（+5.94） |

分相位稳态（heter_cache，括号为 180s 版；括号外为 300s 的 heter−LRU 增益）：

| 背景 | P1 struct | P2 chat | P3 agentic |
|---|---|---|---|
| 0.5× | 0.793（+0.62pp）**−0.32pp**（−0.94） | 0.641（−1.70pp）**+2.70pp**（+4.40） | 0.812（+1.09pp）**+0.57pp**（−0.52） |
| 1.0× | 0.683（+0.52pp）**+0.04pp**（−0.48） | 0.556（−1.16pp）**+7.11pp**（+8.27） | 0.726（+0.65pp）**+0.98pp**（+0.33） |
| 2.0× | 0.538（+0.39pp）**+1.45pp**（+1.06） | 0.390（+0.29pp）**+8.51pp**（+8.22） | 0.569（−0.12pp）**+2.24pp**（+2.36） |

读法：TTL 抬高把收益**从 chat 挪到 struct/agentic**——chat 自身的稳态在低/中背景下
反而降了 1.2~1.7pp（陈旧 chat 多留一会儿），但 struct 相位对 LRU 的劣势被抹平
（−0.94 → −0.32pp；−0.48 → +0.04pp），agentic 相位由负转正（−0.52 → +0.57pp）。
净效应是小幅正收益，且与 LRU 的差距随背景压力拉大（+0.31 → +4.25pp）。

## 5. 局限

1. **单 seed**（42）：所有差异的置信度未做配对检验；tips：`drift3_run.py --seed 43` 即可复现第二轮。
2. agentic 每相位只有 ~28 个会话（51k token/会话），构成份额 σ≈10pp（gate 已按 2σ 容差）。
3. page_size=8 与生产默认 1 不同（OPT 需要）；四臂统一保证可比，但 page 粒度会翻转 heter 的符号。
4. stationary 对照是**独立 run**（从 0 冷启动），本文只取其末 300s 稳态；严格口径应在同一 run 内做 A/B。
5. 不含 TTFT / 重算税，只有命中率；regret 账本本轮未开。
