# 多轮 chat + one-shot 扫描流：LRU vs MultiTurn
## 1. 实验定位

对比：**LRU**（全局单序基线）与 **MultiTurn**（HeterCache 策略，chat 队内按复用分排序）

## 2. 负载设计

### 2.1 参数

| 维度 | 多轮 chat 流 | one-shot 扫描流 |
|---|---|---|
| 数据 | `TaskData/SharedGPT-multi-turn/*/…jsonl`| 唯一前缀的长 prompt（每次访问不重复） |
| 会话数 / 到达 | 8 条并发，泊松 λ=0.022 会话/s（单会话寿命 ≈360 s） | 泊松到达 |
| 轮数 | 8–14 轮，会话内串行 | 1 轮，不复用 |
| 前缀长度 | 首轮 1.2k → 末轮 5.5k（逐轮增长） | lognormal 中位 3.2k，p95 ≈ 9k |
| 轮间等待 | lognormal 中位 **30 s**，σ=0.3（p10/p90 ≈ 20/44 s） | — |
| 注入量 | ≈ **864 token/s**（8 条 ÷ 30 s × 3.24k） | **F ∈ {0, 150, 400, 800, 1200, 1600} token/s** |
| 并发上限 | 32 | 32 |
| 时长 | 预热 60 s + 统计 600 s，3 个 seed（0/1/2） | 同左 |

池容量 **C = 36,000 token**；chat 自身的工作集约21k（8 条 × 当前前缀均值 2.6k），无扫描时只占池子 58%，
### 2.2 为什么用池周转 vs 重访间隔当旋钮

扫描流把池子换一遍所需时间：

| F (token/s) | 0 | 150 | 400 | 800 | 1200 | 1600 |
|---|---|---|---|---|---|---|
| 总注入 (token/s) | 864 | 1,014 | 1,264 | 1,664 | 2,064 | 2,464 |
| **池周转 C/(864+F)** | 41.7 s | 35.5 s | **28.5 s** | 21.6 s | **17.4 s** | 14.6 s |
| chat 重访（中位） | 30 s | 30 s | 30 s | 30 s | 30 s | 30 s |
| 扫描 token 占比 | 0% | 14.8% | 31.7% | 48.1% | 58.1% | 64.9% |

判据：**池周转 < 重访间隔**时，LRU 无法保证一条 chat 前缀活到下一轮。
## 3. 对照实验

| 实验 | 机制 |
|---|---|
| `LRU` | 全局单一顺序，扫描 token 与 chat 前缀同权 |
| `MultiTurn` | HeterCache 策略：one-shot 段先走→ chat 队内按复用分（`1 - CDF(elapsed)`）排序 | 

---

## 4. 指标定义

| 指标 | 定义 | 来源 |
|---|---|---|
| `chat_hit` | Σ chat 轮命中 token / Σ chat 轮 prompt token | 逐请求 CSV `cached_tokens / prompt_tokens`，按 task 分组 |
| `overall_hit` | 同上，全体请求（被扫描 token 加权） | 逐请求 CSV |
| `chat_ttft_p50/p95` | chat 轮首 token 延迟分位 | 逐请求 `ttft_ms` |
| `scan_ttft_p95` | 扫描请求首 token 延迟 p95（**代价项**） | 逐请求 `ttft_ms` |
| `recompute/turn` | 每轮重算 token = prompt − cached | 逐请求 CSV |
| `victim_src` | 淘汰 token 的来源构成：`one_shot` / `quota:chat` / `quota:fallback` | server log `[HeterCache profile]` |

所有数值为 3 seed 的均值；扫 F 时其余参数不变。

## 5. 结果（构造数据）

### 5.1 命中率

| F (token/s) | 扫描占比 | LRU | **MultiTurn** | Δ |
|---|---|---|---|---|
| 0 | 0% | 90.0 | **93.0** | +0.9 pp |
| 150 | 14.8% | 88.7 | **92.2** | +3.5 pp |
| 400 | 31.7% | 79.3 ±1.3 | **91.1** | +11.8 pp |
| 800 | 48.1% | 58.6 ±1.8 | **89.6** | +31.0 pp |
| **1200** | **58.1%** | **34.2** | **88.2** | **+54.0 pp** |
| 1600 | 64.9% | 21.5 ±1.9 | **87.0** | +65.5 pp |

整体 token 命中率

| F | 0 | 150 | 400 | 800 | 1200 | 1600 |
|---|---|---|---|---|---|---|
| LRU | 92.1 | 75.6 | 54.2 | 30.4 | 14.3 | 7.5 |
| **MultiTurn** | **93.0** | **78.6** | **62.3** | **46.5** | **36.9** | **30.5** |

![命中率 vs 扫描强度](figs/virtual_chat_oneshot/fig1_hit_vs_scan.png)

*图 1：左为 chat 前缀命中率，右为全体 token 命中率；误差棒为 3 seed 标准差。*

- LRU 在 F≈400 开始掉点，与池周转跌破30 s的位置吻合；F=1200 时
  chat 前缀只剩三分之一能活到下一轮。
- MultiTurn 整段接近水平：F=1200 时仍有 88%，F=1600 时 87%。
- 两条曲线在 F=0 时几乎重合（92.1 vs 93.0）
